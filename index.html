AI Production Intelligence

Featured · Event-driven

An incident-management backend that solves the dual-write problem: saving to the database and publishing to Kafka can't be made atomic, so an incident and its event are committed together in one transaction (transactional outbox) and a separate publisher delivers the event afterwards. A Kafka outage never loses or blocks an incident.

POST /api/incidents→ PostgreSQLincident + outbox row, 1 tx→ Outbox publisherpolls every 5s, oldest first→ Kafkaincident.created
  • At-least-once delivery: an event is marked published only after the broker acknowledges it; failures stay pending and are retried on the next poll.
  • Ordering and partitioning: events are sent oldest-first and keyed by incident ID, so all events for one incident land on the same partition.
  • Validated API: Bean Validation on request DTOs, UUID identifiers, and OpenAPI/Swagger docs.
  • Local environment: Docker Compose for Kafka and PostgreSQL with a health-checked database and no secrets in the compose file.
